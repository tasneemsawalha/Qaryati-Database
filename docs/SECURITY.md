# Security / operations decisions

- Passwords: random 16-byte salt, Node scrypt (64-byte derived key, default N=16384/r=8/p=1), timing-safe comparison. Passwords are 12–128 characters. A dummy hash reduces nonexistent-account timing differences. Login/register are throttled together per IP (10/min default).
- Sessions: 32 random bytes (256 bits), SHA-256 digest only in the database, configurable TTL (1 hour default, at most 24 hours), explicit logout revocation. Changing a user's role revokes all of their sessions. Registration always creates READER; administrator CLI is an explicit deployment operation.
- Transport: use TLS at a reverse proxy when externally deployed. Tokens are bearer credentials; do not put them in URLs or logs. CORS is an explicit origin allowlist; cookies/credentials are not enabled. No forwarded-IP trust is enabled by default; behind a proxy configure its exact trusted boundary and shared rate limiter before exposing the service.
- Input: whitelist/forbid unknown fields, constrained DTOs, 128 KB JSON limit, pagination cap, version preconditions. ORM and tagged SQL prevent SQL injection. External URLs are fixed server-side, not supplied by clients.
- Logs: JSON method/path/status/duration and generated request ID. Bodies, authorization headers, query strings and database URLs are excluded. Unexpected errors log their type and request ID, not raw database messages. Use INFO for request summaries, ERROR for 5xx. Add operational alerts and retention in an actual deployment.
- Audits: immutable through the API; before/after plus actor/time in the same transaction. Use database privileges/backups to prevent administrative tampering; app-level audit is not a cryptographic ledger. Restrict audit reads to VERIFIER/ADMIN.
- Before sharing or publishing, inspect the actual archive and exclude `.env`, account passwords, session tokens and credential-bearing database dumps. Include `.env.example` with placeholders only; each teammate supplies local secrets. Ignore rules do not remove files from manually created archives, and an archive must not be described as secret-free without inspecting its contents. The fixed disposable benchmark database password is test-only and must never be reused for deployment.
- Docker uses an unprivileged application user and keeps database/API ports on loopback. The image retains Prisma CLI/development dependencies to run migrations and verification in this course environment; a production pipeline should use a dedicated migration image and a pruned runtime image.
- Single-instance limitations: cache and rate limits are process-local; public registration reveals duplicate email status; there is no email verification, account recovery, or MFA in this course scope. Do not claim internet production readiness without operational review.
